# 05. Data Model

## Persistence boundary (as-is)

The current persistence model is intentionally small: one PostgreSQL table, `assumptions`, mapped by the JPA entity `com.finance.planner.entity.Assumption`.

### `assumptions`

| Column group | Fields | Notes |
|---|---|---|
| Identity | `id` | Generated primary key; service reads the first row ordered by id |
| Income | `base_salary`, `january_multiplier` | Base salary and January multiplier |
| Expenses | `living`, `child_through_2026`, `child_q1_2027`, `child_from_apr_2027`, `rent_through_jan_2027`, `rent_from_feb_2027` | VND integer amounts |
| Debt | `loan_principal`, `fixed_payment`, `nov_interest`, `dec_interest`, `payoff_interest`, `payoff_interest_confirmed` | Payoff interest may be null; confirmation is separate |
| Savings | `starting_savings` | Initial cumulative savings balance |
| Raises | `raise_2027` … `raise_2030` | Decimal rates |
| Audit | `created_at`, `updated_at` | Local date-time fields |

## Ownership and cardinality

- Current product behavior assumes one household and one logical assumptions record.
- The database entity has a generated `id`, but there is no user/household ownership relation.
- `AssumptionService` selects the first row; there is no scenario or multi-profile identity.
- Do not add multi-household or scenario identity without an approved product requirement (deferred F-06/F-08).

## Forecast data

Forecast month and annual rows are response DTOs generated by `ForecastService`; they are not currently persisted as separate database records. Forecast is recalculated from the assumptions passed to the forecast endpoint.

## Sensitive data and handling

- Assumptions can reveal household income, expenses, debt and savings. Treat database backups, exports and logs as sensitive.
- Do not log full assumption DTOs or CSV contents in normal application logs.
- Do not commit `.env`, real database passwords, real household values or exported CSVs.
- Keep test fixtures synthetic and clearly labeled.
- Restrict database/network access and protect local backup files.

## Schema lifecycle (current gap)

Current runtime uses Hibernate `ddl-auto=update` by default; `docker-compose.yml` also sets it to `update`. Versioned migrations are not configured in the inspected project state. Finding F-07 tracks the move to repeatable schema migrations and disabling automatic schema mutation.
